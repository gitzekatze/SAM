# Review 2026-11-09: GTK GUI and recent backend changes

Scope: `crates/sam-gtk` (new GTK 4 / libadwaita GUI, about 3,400 lines) and
the backend changes since 2026-11-08 (Bubblewrap only, gamepads, input
method, pasta status channels, running lock, overlay removal, NVIDIA
modules, three-way merge of preview settings). Plus a feature-coverage
check: does the GUI expose everything the core can do?

Overall: no security problems found. Untrusted text (names, paths,
warnings, app output) is escaped or shown as plain text everywhere;
commands are run with argument vectors, never through a shell; dangerous
D-Bus names use the core's own check. One real bug (lost edits), several
small UX issues, and a list of features the GUI does not show.

## Findings in the GUI code

| # | Severity | Finding |
|---|---|---|
| G1 | Medium | **Quick edits can be lost.** Every setting change starts its own `sam-jail profile set` in the background. Two changes in quick succession run in parallel and can finish out of order, so the older settings may be saved last and the newer change is lost. The same applies to previews of AppImages without a sandbox. Fix: send saves one after another (or only the latest). |
| G2 | Medium | **Remove always deletes the app's private data** (its settings, logins, saved files). The CLI has `remove --keep-data`; the GUI offers no choice. Fix: an option in the confirmation ("Keep the app's settings and files"). |
| G3 | Low | **The app list is rebuilt on every selection and after every saved setting.** Keyboard focus is lost (arrow-key navigation stops) and every change also re-reads all AppImages (`discover`). Fix: update rows in place; refresh only the changed app. |
| G4 | Low | **Dropped files are not checked.** Dropping a folder or a non-AppImage file adds it as a location file. Fix: folders become folder locations; other files are ignored with a message. |
| G5 | Low | **Presets picked before a sandbox exists skip the compatibility check** ("this preset removes permissions the app likely needs"). Sandboxed apps get the check. |
| G6 | Low | **Some app states are never shown:** *Needs review*, *Compatibility risk* and *Unsafe* badges. Only stale, broken and missing appear. An app created with the CLI (without `--accept`) stays "Needs review" with no way to confirm it in the GUI. |
| G7 | Cosmetic | Two unused type aliases in `window.rs`; the app is non-unique, so two SAM windows can be open and write the same config. |

## Findings in the backend changes

No problems found. Checked: the pasta wrapper (FIFOs opened by `/bin/sh`
inside pasta's namespace; readers end when the sandbox exits even if no
writer appears), the running lock (held only by a real launch, stale
folders cleaned only when the runner's PID is gone), overlay removal
(permissionless `work/work` unlocked first), NVIDIA module binds (only
`/sys/module/nvidia*`, read-only, only with GPU access), the three-way
merge (user changes win, lists are taken as a whole), the theme migration.

## Feature coverage: what the GUI does not show

Covered: all 47 permissions in the catalog, preview and Create Sandbox,
Launch, Remove, presets (pick, save, edit, duplicate, import, export,
delete, apply to), first-run hints, repair steps and undo, diagnostic
run, bug report, re-extract and relocate, the menu entry switch, system
check, change check, cleanup, nearly all preferences.

Not in the GUI (works only with `sam-jail`):

| Feature | CLI | Notes |
|---|---|---|
| Launch arguments | set by repair (`--no-sandbox`) | Visible only inside the sandbox command; removable only with "Undo all repairs". No CLI command to edit them either. |
| Compatibility mode on/off | `sam-jail compat` | Turned on by a repair step; the GUI shows the broader settings but no "compatibility mode is on" indicator and no off switch. |
| Environment variables with values | profile `environment.set` | The GUI only passes host variables through. |
| Extra sockets | profile `sockets.custom` | |
| D-Bus names the app may own / must not reach | profile `dbus.session.own`, `dbus.session.deny` | |
| Hide or restore unsandboxed menu entries later | `sam-jail menu list/hide/restore` | Only offered once, when the sandbox is created. |
| Keep the app's data when removing | `sam-jail remove --keep-data` | See G2. |
| Other logs and log history | `sam-jail logs --kind extract/detect/diagnose`, `--list` | GUI shows only the latest launch log. |
| Re-run detection and recommendation | `sam-jail redetect` | |
| Mark as reviewed | `sam-jail review` | See G6. |
| Check one app / try all apps | `sam-jail doctor <app>`, `sam-jail selftest` | |
| Extraction folder | `config extraction.location` | Shown, not editable. |

Dead settings in the core (not used anywhere, so not worth a GUI):
`general.automatic_scanning`, `general.ui_mode`, `network.allowed_hosts`
(the filtered network mode is not enforced) and the system-bus
`allow` / `own` / `deny` lists (the system bus is all or nothing).

## Follow-up (same day)

Done: G1 (saves are sent one after another; only the newest waiting change
is kept), G6 (state badges in the header and the list, *Mark as Reviewed*),
and from the coverage list: launch arguments, compatibility-mode switch
(now reversible: turning it off restores the settings from before),
environment variables with values, the hide/restore switch for other menu
entries, every log with a picker, re-run detection. New CLI pieces:
`sam-jail args <app> [--stdin]`, `sam-jail logs <app> --file <path>`.
Open: G2-G5, G7, extra sockets and D-Bus own/deny lists, per-app check
and self-test, editable extraction folder.
