# Real AppImages, 2026-11-10

18 real AppImages run through SAM's whole flow: recommendation, Create
Sandbox, sandbox check, a 15-second test start, first-run hints and repair
steps. Run with `tests/real-apps/run.sh` (invisible KWin session, private
D-Bus, fake home; no sound server, so audio checks are not applicable).
Downloads came from each project's official release page and matched the
published SHA-256, except OpenRA, whose release publishes none (HTTPS from
GitHub only).

fix after the first failed start.

## What the first round found, and the fixes

| Problem | Cause | Fix |
|---|---|---|
| Every app on *Local network only* lost the session bus; Electron apps did not start ("Running as root without --no-sandbox") | Inside pasta's user namespace Bubblewrap mapped the app to root; the D-Bus proxy rejected it | `--uid`/`--gid` of the user always; integration test for the mode |
| KeePassXC exited at once | Its AppRun uses `systemd-run --user` whenever that exists; the sandbox blocks it (rightly: with full D-Bus it would start the app outside) | `systemd-run` is a stand-in inside the sandbox that runs the command directly; `flatpak-spawn` refuses |
| Audacity crashed, SAM gave no hint | Audacity forces X11 and logs the Qt error to stdout; only stderr was analysed | Log analysis reads both streams and suggests *Turn on X11* |
| AnythingLLM and Open WebUI were "Likely won't start" but ran fine | Bundled musl (Alpine) variants of Node/Python modules counted as missing libraries; `libdl.so` not matched to `libdl.so.2` | musl variants are skipped (noted); unversioned names accept the versioned library |
| Neovim got GPU, Wayland and "The window may not appear" | `Terminal=true` was ignored by the recommendation; Launch started it without a terminal | Terminal programs get no display, GPU or D-Bus, no window hints, and Launch opens a terminal |
| OpenRA offline with no hint | .NET loads networking at run time, so detection sees none | Games without network get *No online play* |

## Not covered

- **Type 1 AppImages:** no trustworthy current app still ships one; SAM's
  built-in Type 1 test images cover extraction.
- Windows were not looked at (invisible session): "kept running for 15 s"
  means the app started and did not crash, not that every feature works.
- No sound server in the test session, so audio was not exercised.
- Launching a terminal program from the window (opens a real terminal) was
  not tested; the menu entry path (`Terminal=true`) was, with Neovim in a
  pseudo terminal.
