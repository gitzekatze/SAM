# Project analysis 2026-11-11

The state of SAM - Sandboxed AppImage Manager after phases 1, 2, 3 and 5
(0.1.0 plus the *Unreleased* changes), with the improvements worth making
next. The analysis ran together with a sweep for old names and outdated
documents (see the end of this page).

**Overall:** the core is in good shape. There are 105 tests, all of which run
in CI on Ubuntu 24.04, a breakout test suite, versioned data files and no
open review findings. The biggest gains now are in four places: two gaps in
the sandbox around audio and Wayland, AppImage formats the built-in reader
cannot unpack, automatic refresh of the list, and splitting three very large
source files.

Priority: **P1** do before the public beta, **P2** soon after, **P3** later.
Effort: **S** hours, **M** a day or two, **L** a week or more.

> **Update, later on 2026-11-11:** every item is done except two. C3
> (updates) was set aside on purpose. T3 (real systems) needs Fedora and
> openSUSE machines. See [What was done](#what-was-done-for-p1) and
> [P2 and P3](#what-was-done-for-p2-and-p3) at the end.

## Security

### S1 · *Audio* hands out the full PipeWire socket (P1, M)

With *Audio* on, the sandbox gets both the PulseAudio socket and the raw
PipeWire socket (`pipewire-0`). PipeWire limits apps from Flatpak, but SAM
apps look like ordinary programs to it. So an app with *Audio* can likely:

- open camera nodes, bypassing the *Webcam* permission;
- record other apps' sound;
- read screen-cast streams.

This is still to be confirmed with a breakout test.

**Fix:**

1. *Audio* gives only the PulseAudio socket (`pipewire-pulse`), which plays
   and records sound but exposes no cameras or video.
2. The PipeWire socket comes only with *Webcam* or *Screen sharing*.
3. Later: a restricted socket per app through PipeWire's security context,
   as Flatpak 1.16 does.

Add a breakout test that lists PipeWire nodes from inside the sandbox.

### S2 · Block `io_uring` in the baseline filter (P1, S)

`io_uring_setup`, `io_uring_enter` and `io_uring_register` are allowed.
`io_uring` is one of the most common sources of kernel privilege escalations,
and Docker, ChromeOS and Android block it by default. Desktop apps hardly
use it; where they do, they fall back to normal I/O.

**Fix:** block it with `EPERM` in the baseline filter, then re-run the 18
real AppImages.

### S3 · Wayland security context (P2, M)

Every sandboxed app gets the normal Wayland socket. On compositors with
privileged protocols, such as clipboard managers (`data-control`), screen
capture (`screencopy`, `image-copy-capture`) and virtual keyboards, it could
use them too.

**Fix:** create a socket per app with `wp_security_context_v1` (supported by
KWin, Sway, Hyprland and GNOME 47+). The compositor then knows the client is
sandboxed and hides those protocols. The sandbox check should report whether
the context was set.

### S4 · Supply chain checks and signed releases (P1, S)

**Fix:**

- `cargo deny` (advisories, licences, duplicate crates) in CI.
- Dependabot for the GitHub Actions and crates.
- Make release signing the default in `scripts/release.sh`. `SIGN_KEY`
  already exists but is optional, so the AUR and COPR builds have nothing
  to verify.

### S5 · Show AppImage signatures (P3, M)

AppImages can carry an embedded signature (`.sha256_sig`, `.sig_key`).

**Fix:** show *Signed by …* or *Not signed* on the app page. After an update,
warn if the signing key changed.

The outside security review stays on the list from phase 2.

## AppImage compatibility

### C1 · lz4 and lzo payloads (P1, S)

Detection recognises lz4 and lzo SquashFS images, but the built-in reader is
compiled only with gzip, xz and zstd (`backhand` features). Those AppImages
fall back to the AppImage's own extractor, which needs consent and runs the
app's code.

**Fix:** enable the `lz4` and `lzo` features of `backhand`, and add test
images.

### C2 · DwarFS-based AppImages (P2, M)

Newer runtimes (*uruntime*, used by the AnyLinux and pkgforge AppImage
projects, several hundred apps) can carry a DwarFS image instead of
SquashFS. SAM does not recognise it, so these AppImages also fall back.

**Fix:** detect the DwarFS magic. Unpack with `dwarfsextract` inside the
unpacking sandbox when it is installed. Otherwise say clearly what is
missing.

### C3 · Updates (P2, L)

SAM notices when an AppImage file changed, but cannot update one.

**Fix:**

- Read the update information embedded in the AppImage (`.upd_info`:
  zsync, GitHub releases).
- Show *Update available*.
- Download the new file next to the old one, check its signature (S5), swap
  the files, and keep the sandbox and its settings.

The same mechanism can update SAM's own AppImage (already planned).

### C4 · aarch64 (P3, M)

Detection and the library paths know aarch64, but CI, the release workflow
and SAM's own AppImage are x86_64 only.

**Fix:** add an aarch64 runner to CI (GitHub has free arm64 Linux runners)
and build an aarch64 AppImage.

## Stability

### T1 · Version handshake (P1, S)

The window drives everything through `sam-jail --json`. If the window and
the command line come from different versions (a partial update, or
`SAM_CLI` pointing at an old build), JSON fields go missing silently.

**Fix:** `sam-jail --json version` returns an interface level. On a
mismatch, the window shows a clear message instead of half-empty pages.

### T2 · Window tests in CI (P2, M)

The window has no automated tests. `sam-jail-gui --screenshot` already
renders headlessly with Broadway.

**Fix:** a CI step that opens every page (start page, app page before and
after *Create sandbox*, Presets, Diagnostics, Preferences, User Guide)
against a test data set and fails on GTK warnings or errors.

### T3 · Real systems (P1, M)

So far only CachyOS has run SAM day to day. Phase 4 is still open:

- Fedora with SELinux enforcing;
- openSUSE Tumbleweed (AppArmor);
- Ubuntu 24.04 desktop (AppArmor user-namespace restriction, with the
  explanation SAM gives).

Run the 18-app harness (`tests/real-apps/run.sh`) on each.

## Performance

### P1 · Watch the locations (P2, M)

The list refreshes only on start, on *Refresh* and after SAM's own actions.
Each refresh starts `sam-jail discover`, which looks at every location again.
An AppImage that was just downloaded only appears after *Refresh*.

**Fix:** watch the locations with `gio::FileMonitor` and update single
entries when files appear, change or disappear. This is also friendlier.

### P2 · Disk use of unpacked apps (P3, M)

Each sandbox keeps a full unpacked copy next to the AppImage, so large apps
need double the space.

**Fix:**

- Show the space per app (U4).
- Offer *Free space*: delete the unpacked copy and unpack again on the next
  start.
- Later: run directly from the SquashFS image through a read-only
  `squashfuse` mount inside the sandbox.

## Structure

### A1 · Split the largest files (P2, M)

| File | Lines | Split into |
|---|---|---|
| `sam-gtk/src/app_page.rs` | 1,776 | header and buttons, settings, troubleshooting, logs |
| `sam-runner/src/ops.rs` | 1,415 | discover, add and remove, maintain, presets |
| `sam-jail-cli/src/main.rs` | 1,371 | one module per command group |

### A2 · One code format (P3, S)

The code is formatted by hand with long lines; plain `cargo fmt` would
rewrite more than 9,000 lines.

**Fix:** add a `rustfmt.toml` close to the current style (e.g.
`max_width = 160`), reformat once in its own commit, and check it in CI.

### A3 · Leftovers of the multi-backend design (P3, S)

SAM has one sandbox, but the code still has a `Backend` trait, a `select`
module and a crate called `sam-backend-bubblewrap`.

**Fix:** fold the trait away and rename the crate, for example to
`sam-sandbox`. This has no effect for users; it is for clarity.

### A4 · Document the JSON interface (P2, S)

`--json` output is what the window and scripts rely on, but it is not
described anywhere.

**Fix:** a short reference per command, and the 0.x rule from the changelog
(the minor version may change it) stated there.

## Usability

### U1 · The AppImage list grows with the locations (done)

The locations were in a fixed area that scrolled after two and a half
entries. They now sit in the scrolling left column: each new location
lengthens the list, and the Downloads switch and the AppImages move down.

### U2 · Translations (P2, M)

All text is English and hard-coded.

**Fix:** move the strings to gettext (the GTK standard) and set up a
translation platform, such as Weblate, when the project goes public. German
would make a natural first translation.

### U3 · Accessibility (P2, S)

Several buttons show only an icon (add folder, add file, refresh, remove
location, the logo). They have tooltips, but screen readers need an
accessible label.

**Fix:**

- Set an accessible label on each icon-only button.
- Check keyboard navigation through both columns.
- Check the green and blue labels for contrast in the dark style.

### U4 · Disk use and cleanup (P3, S)

**Fix:** Diagnostics shows the space used by unpacked apps, private homes
and logs, with *Delete* per item (see P2).

## What was done for P1

- **S1:** *Audio* binds only the PulseAudio socket. The raw PipeWire socket
  is the new advanced permission `audio.pipewire` (*Direct PipeWire access*,
  High risk), offered as a repair step when an app with sound still tries to
  reach PipeWire directly. The sandbox check tests that the socket is
  absent, and `doctor` warns when PipeWire runs without `pipewire-pulse`.
  A correction to the analysis above: recording other apps' sound through
  their monitor sources is possible over PulseAudio too, as in Flatpak. What
  the change closes is cameras and screen-cast streams.
- **S2:** `io_uring_setup`, `io_uring_enter` and `io_uring_register` are
  refused with `EPERM`, also with nested sandboxes. The breakout test checks
  it.
- **S4:** `deny.toml` and a `cargo deny` job in CI cover advisories,
  licences, banned crates and sources; it passes. Dependabot is set up for
  Actions and crates. `scripts/release.sh` now needs `SIGN_KEY` (or
  `UNSIGNED=1`) and also signs `SHA256SUMS`. SAM's crates are marked
  `publish = false`.
- **C1:** lz4 is unpacked by the built-in reader, tested with backhand and
  with `mksquashfs` images. **lzo is not:** its only Rust decoder
  (`rust-lzo`) is GPL-2.0-only, which cannot be combined with SAM's
  GPL-3.0-or-later. `deny.toml` bans it. lzo AppImages, which are very rare,
  still unpack without running their code, through the host's `unsquashfs`
  when it is installed.
- **T1:** `sam-jail version` reports the version and `JSON_INTERFACE`
  (`sam_core`). At start, the window shows *SAM's Parts Do Not Match* when
  the tool reports another level or has no version command.
- **Real apps:** the 18 real AppImages were run through the harness again
  with these changes.

## What was done for P2 and P3

- **S3:** each app gets its own Wayland socket made with
  `wp_security_context_v1` (engine `io.github.gitzekatze.SAM`, app id,
  instance).
  - Checked on KDE Plasma: the app no longer sees `ext_data_control` or
    `org_kde_kwin_fake_input` (63 instead of 70 interfaces).
  - `display.wayland_privileged` turns it off for clipboard and screenshot
    tools.
  - `doctor` and the launch log say whether the desktop supports it.
- **C2:** DwarFS payloads are recognised and unpacked with `dwarfsextract`
  inside the extraction sandbox. Detection is unit-tested. Tested for real
  with the official dwarfs 0.15.8 tools: a DwarFS AppImage made with
  `mkdwarfs` is unpacked inside the unpacking sandbox and starts in its
  sandbox; without `dwarfsextract`, SAM says what to install and runs
  nothing from the AppImage. (This test found that tools outside `/usr` were
  missing inside the unpacking sandbox; fixed.)
- **P1:** the locations are watched with `gio::FileMonitor`; the list
  refreshes 1.5 s after a change, ignoring hidden files and unfinished
  downloads.
- **U3:**
  - Icon-only buttons get an accessible name.
  - The blue label keeps 4.5:1 contrast in light and dark style.
  - Not done: keyboard navigation through both columns was not tested by
    hand.
- **U2:** gettext through GLib. 122 strings of the window are marked, and
  German covers them all.
  - Still English: permission texts, hints, warnings and the user guide
    (`docs/translating.md`).
- **T2:** `tests/gui/smoke.sh` opens every page; CI runs it on Broadway and
  keeps screenshots. It found a real bug right away: the labels under an
  app's name were cut off when they wrapped. That is fixed.
- **A4:** `docs/json-interface.md`.
- **S5:** embedded signatures are checked with `gpgv` in a throwaway keyring.
  - The result shows in the details and in `info`.
  - An invalid signature gets a warning, and so does an update signed with
    another key or no longer signed.
  - An end-to-end test signs a test AppImage with a throwaway key.
- **P2/U4:**
  - Disk space per app: in the details, in Diagnostics and with
    `sam-jail space`.
  - *Free Space* / `sam-jail free-space` deletes the unpacked copy; the
    next start unpacks it again.
- **C4:**
  - The AppImage builds for x86_64 and aarch64 (pinned runtime digests).
  - The Release workflow builds both.
  - CI tests on ARM once the repository is public.
  - The breakout test uses each architecture's syscall numbers.
  - Every crate except the window type-checks for aarch64 here.
- **A3:**
  - The crate `sam-backend-bubblewrap` is now `sam-sandbox`.
  - `sam_core::sandbox`, `sam_runner::bwrap::check`.
  - `advanced.extra_bwrap_args`; old profiles still load.
- **A1:** `ops.rs`, the command line's `main.rs` and `app_page.rs` are
  split into modules of 26 to 690 lines.
- **A2:**
  - `rustfmt.toml` (`max_width = 160`); the tree was formatted once in its
    own commit, listed in `.git-blame-ignore-revs`.
  - CI runs `cargo fmt --check`.
