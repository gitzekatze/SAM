# Mutation testing before 0.2.0 (2026-11-15)

> **What this is:** cargo-mutants changed the code of the four crates that
> handle untrusted input and build the sandbox (`sam-sandbox`, `sam-runner`,
> `sam-intake`, `sam-detect`) on purpose, one small change at a time, and ran
> all of SAM's tests against each change. A change the tests do not notice
> ("missed") shows a promise that no test really checks.

## Result

| | Mutants |
|---|---|
| Tested | 2,821 |
| Caught by a test | 2,280 |
| Caught by a timeout (the change made SAM hang) | 29 |
| Missed | 314 |
| Not buildable (no result) | 198 |

**88.5 % of the buildable changes were caught** before the fixes below.

The whole suite ran for each mutant (`--test-workspace=true`): the tests of
one crate live partly in other crates, and with only the crate's own tests
most "missed" results were false.

## What it found and what was fixed

Each fix has a test that fails without it.

- **A real bug:** when SAM's own SquashFS reader stopped at the size limit,
  the error lost its `extraction-limit` code, so the window could not explain
  the limit (`unpacking_stops_exactly_at_its_limits`).
- **Unpacking limits** (file count, size, time) are now checked exactly at
  the boundary, together with file modes
  (`unpacking_stops_exactly_at_its_limits`, `only_an_exceeded_limit_counts_as_one`).
- **The sandbox command:** the app folder stays read-only without the grant;
  SAM's own folders stay hidden inside a granted folder; credential files and
  folders are masked; home protection is prepared only for a writable home;
  only proper variable names are set (five tests in `sam-sandbox`, module
  `guard_tests`).
- **The terminal relay:** a doubled ESC, or a sequence cancelled by CAN or
  SUB, cannot smuggle a clipboard code past the filter
  (`a_doubled_escape_does_not_smuggle_a_clipboard_code`).
- **Update integrity:** the block checksums and the SHA-1 of a download are
  pinned to their standard test vectors
  (`block_checksums_match_the_zsync_definition`,
  `the_download_checksum_is_sha1_of_the_whole_file`).

## What stays missed, and why

| Area | Missed | Why it is acceptable for now |
|---|---|---|
| Delta updates and downloads (`zsync.rs`, `updates.rs`, parts of `ops/maintain.rs`) | 68 | The download path needs an HTTPS server, which the tests do not have. A wrong delta plan produces a wrong file, which the SHA-1 check (now pinned) refuses. **Follow-up:** a local HTTPS test server. |
| App analysis (`elf.rs`, `appimage.rs`, `classify.rs`) | 46 | Library, toolkit and processor detection. A wrong answer gives a worse recommendation or message, not a weaker sandbox. |
| Signatures (`signature.rs`) | 10 | The GnuPG test runs in CI only (`SAM_TEST_GPG=1`), because signing starts a gpg-agent in the user's runtime folder. |
| Terminal relay internals (`pty.rs`) | about 25 | Raw mode, buffer sizes and loop bounds; the security filter itself is now covered. |
| Sandbox command (`sam-sandbox`) | about 20 | The remaining changes only make the sandbox stricter (more paths hidden or read-only) or change notes. |
| Repair advice, sandbox check, overview, records | about 145 | Texts, display fields and record fields: a wrong value shows wrong information but grants nothing. |

## How to run it again

See [the release checklist](../releasing.md). Run it through a guard: a
mutant that breaks a loop can write without end (one such run filled the disk
on 2026-11-15). The guard caps each file at 4 GB and stops the run when the
scratch folder grows past 30 GB or the disk runs low.
