# Real AppImages in SAM (2026-11-20)

> **What this is:** every AppImage of SAM's test sets went through SAM's whole flow
> in a hidden desktop session: SAM unpacked and analyzed it, created a sandbox with
> its own recommendation, checked the sandbox from the inside, and started the app.
> If the app did not start, SAM's repair steps were tried one at a time.
> Made with `tests/real-apps/run.sh` and `tests/real-apps/table.py --markdown`.

**Total:** 240 AppImages; 226 start with SAM's recommendation; 3 start after one repair step; 10 do not start; 1 turned away (built for another processor); 209 showed a window within 20 seconds.

A window can be missing for good reasons: tray-only apps, command-line tools and
apps that wait for a first-run question show none in the hidden session.

## Since the run of 2026-11-18

The same 240 AppImages, on the same computer, after the audit's fixes
(`main` at 707cdd3; the [report of 2026-11-18](real-apps-2026-11-18.md)
was made on 05b5875).

- **5 apps start that did not:** Gopeed, Reqable and CherryTree (SAM now
  learns the bus name an app asks for and restarts it once), Widelands (its
  private home now has `~/.local/share`), Chatterino (the hidden desktop now
  has a silent sound device).
- **12 more windows:** apps that open sound before their window waited for
  a sound device the hidden desktop did not have (audacity, OpenRA, rpcs3,
  SuperTux, xemu, Zrythm and others).
- **4 apps that started do not**, each explained below: Dolphin, ImHex,
  Nextcloud, Dust3D.

## Why the 10 do not start

| AppImage | Why |
|---|---|
| AntiMicroX | Needs the `uinput` device to act as a game pad; SAM gives no app that device. |
| appimagelauncher-lite | A command-line tool that ends at once when started without an option. |
| KOReader | Takes this computer for an e-reader (CachyOS ships a program called `hwdetect`, which KOReader looks for) and stops; it does the same without SAM. |
| AppFlowy | Needs `libkeybinder-3.0`, which is not installed on this computer; SAM names the missing library. |
| Dolphin, ImHex, Plover | SAM offers the step that helps ("Turn on X11", "use your system's copy of libsystemd"), but the step comes from what the app printed, which the app controls, so SAM applies it only after a person confirms it. This run does not confirm steps. |
| Nextcloud | Nextcloud is also installed on this computer. SAM does not let the AppImage take over the installed app's bus name, which would give it the messages meant for that app. |
| Dust3D | Used about 23 GB of memory while starting and reached this run's own memory limit (24 GB). |
| Mangayomi | Now gets its bus name, then stops in GTK's image loader, which wants to start a sandbox of its own inside SAM's. Being looked into. |

## The sandbox check's 10 "Sound" failures

Ten apps with long names (Audacity, GIMP in two versions, MuseScore,
ONLYOFFICE, mpv, Heroic, OpenShot, Dolphin and Another Redis Desktop
Manager) had no sound
in their sandbox, and some lost their own Wayland connection or their
session bus: the path of a connection SAM made for them was longer than
Linux allows. SAM fell back to nothing less safe and said so. Fixed in
#87; the 12 apps with the longest names, run again on the fix
(2026-11-21), had no failed check and no such warning.

from outside whether the app read the file. The window is checked in the screenshot
after 20 seconds, its text read for error messages, and the app's own messages for
crashes, missing libraries and refused access.
