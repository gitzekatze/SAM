# Long fuzz run before the release (2026-11-20)

> **What this is:** fuzzing feeds SAM's readers of untrusted files with
> randomly damaged input, many times over, and checks that nothing crashes,
> hangs or writes outside its place. CI runs each fuzz test briefly on every
> change; this is the long run before the release, with a new random seed,
> so it reaches inputs the short runs never try.
>
> On `main` at 707cdd3, seed 3010946712 (anyone can repeat the run with
> `SAM_FUZZ_SEED=3010946712`), sandbox tests required
> (`SAM_REQUIRE_SANDBOX=1`). The run took 49 minutes.

## Result

**All 9 fuzz tests passed.** No crash in SAM, nothing written outside the
folders a reader may use.

| Test | Rounds | What it feeds |
|---|---|---|
| `changed_appimages_never_crash_or_escape_the_unpacker` | 100,000 | damaged AppImages, through unpacking (SquashFS and DwarFS) |
| `changed_programs_never_crash_the_analysis` | 100,000 | damaged programs (ELF), through the library analysis |
| `changed_text_inputs_never_crash_the_parsers` | 100,000 | damaged menu files, settings, records and tool output |
| `changed_desktop_files_never_crash_the_reader` | 10,000 | damaged menu files inside AppImages |
| `changed_signature_and_update_sections_never_crash_the_readers` | 10,000 | damaged signature and update sections |
| `changed_zsync_controls_never_crash_planning_or_assembly` | 10,000 | damaged update instructions (zsync) |
| `the_preview_reader_panics_only_inside_the_squashfs_library` | 10,000 | damaged images, through the preview (9,529 read) |
| `nothing_past_the_filter_reaches_past_the_terminal` | 100,000 | random bytes through the terminal filter |
| `the_model_recognizes_the_known_attacks` | 100,000 | random terminal input against the filter's model |

## One finding in a library SAM uses

Seven of the damaged AppImages made the SquashFS library (backhand 0.25.5,
`v4/reader.rs` line 63) stop with "attempt to add with overflow" while
reading. This is a fault in the library, not in SAM: SAM runs such readers
so that a crash there is contained (in its own sandboxed reader process, or
caught inside SAM), and reports the AppImage as damaged. Nothing was
written outside, and the test passed, as it checks exactly that. A report
to the library's authors is planned.
