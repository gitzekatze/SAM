# Mutation testing before the release (2026-11-20)

> **What this is:** cargo-mutants changed SAM's code on purpose, one small
> change at a time, and ran all of SAM's tests against each change. A change
> the tests do not notice ("missed") shows a promise that no test really
> checks.
>
> This run covers **every line of Rust code changed since the security
> audit of 2026-11-18** (commit 05b5875), in all nine parts of SAM, the
> window included, on `main` at 707cdd3. That is where the audit's fixes
> went in, so it checks that each fix has a test that would notice it
> breaking. The full run of the four input-handling parts is the
> [report of 2026-11-16](mutants-2026-11-16.md).

## What the 171 missed changes were

| Group | Missed | Meaning |
|---|---|---|
| The window (`sam-gtk`) | 52 | Its flows run as separate scripts in CI (window-flows, window-flows-gnome), which cargo-mutants does not run. These say nothing either way. |
| Text on the command line | about 45 | The wording of a message, or when a line is printed (`sam-jail-cli` main.rs and output.rs, some start messages). No effect on what a sandbox allows. |
| Same result anyway, or unreachable | about 25 | For example `\|` instead of `^` on bits that never overlap, error paths of system calls that do not fail in a test, timing boundaries. |
| Size limits not tested at their exact edge | 5 | A limit of `256*1024` changed to `256+1024` went unnoticed: a smaller limit only refuses more. |
| **Real test gaps** | about 39 | Below. |

None of the real gaps was a hole in SAM's protection: the code did the
right thing; the tests would not have noticed if it stopped doing it.

## The real gaps, and what closed them

Pull request #87 adds a test for each. Run again against the same kinds of
change on the new code (121 and 55 mutants on the lines concerned), the
tests now notice:

- a sound relay running outside its own sandbox counted as "held" (`sam-jail doctor` would not have seen it);
- whether a user folder such as Documents counts as writable, with Documents set to the folder that holds the real `~/.bashrc`;
- a test's "skipped" or "not here" that goes unrecorded, or a skip allowed where CI must prove everything;
- secrets in a bug report written with more after the secret word (`GITHUB_TOKEN_2=…`, `"password-hash": …`), with extra spaces or quotes, followed by `;` or `,`, or a report that ends with such a word;
- the warnings about missing protection layers and about files SAM moved aside, printed when there is nothing to say or not printed at all;
- protected folders made in the home where the start does not show them;
- the hint to start without Chromium's own sandbox, and the graphics hint, offered to the wrong apps; SAM's reading of whether the computer blocks Chromium's sandbox is now compared with a real try;
- a preset from a newer SAM moved aside like a damaged one; `preset export` without a file; the IPv6 loopback check.

Of the 46 missed changes in the lines these tests aim at, 40 are caught
now. The 6 left are explained: 4 in a filter of the start code whose rule
is tested where the repair steps are made; one place in the bug-report
redaction that cannot be reached (two hidden values never meet without a
separator); and "Chromium's sandbox is never blocked", which only a
computer that does block it can show (the test compares with a real try
and catches the opposite here).
