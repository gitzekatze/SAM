# Mutation testing, full run (2026-11-16)

> **What this is:** cargo-mutants changed the code of the four crates that
> handle untrusted input and build the sandbox (`sam-sandbox`, `sam-runner`,
> `sam-intake`, `sam-detect`) on purpose, one small change at a time, and ran
> all of SAM's tests against each change. A change the tests do not notice
> ("missed") shows a promise that no test really checks.
>
> This is one complete run on `main` at 7c01931, without `--iterate`, so
> every change has its own recorded result. It replaces the run of
> 2026-11-15, whose numbers could not be split exactly.

## Conditions of the run, and one correction

The run used no special variables, so the tests that only run in CI with
`SAM_TEST_GPG=1` did not run. That affects `sam-detect/src/signature.rs`:
in the full run 16 of its 50 buildable changes were missed (68 %). Run
again on its own with `SAM_TEST_GPG=1`, as CI runs it, only **4 of 50**
were missed (**92 %**). The numbers above are the full run as recorded;
with that correction, 412 changes were missed (85.2 % caught).

**Correction (2026-11-17): the real sandbox tests did not run.** The run
tested only the four mutated packages (`cargo test --package=…`), so SAM's
helper `sam-jail-run`, which is part of `sam-jail-cli`, was never built,
and every test that needs it skipped itself: the breakout test, the
hostile AppImages, the permission matrix, the sandbox check and the
end-to-end sandbox test. The command-line tests (`sam-jail-cli`) did not
run either. The numbers above are therefore a lower bound, above all for
the code those tests prove (the sandbox check, the terminal relay, the
kernel layers, launching). A run with `--test-package sam-runner
--test-package sam-jail-cli` and `SAM_REQUIRE_SANDBOX=1`, which refuses
any skip, replaces them; tests now also find the helper of their own
build without `PATH` being set (`find_helper`).

Mutants that break SAM's cleanup left about 4,300 empty folders in the test
user's runtime folder; they were removed after the run, and later runs use
a runtime folder of their own.

## What follows

The weak files are the ones that prove promises: the sandbox check, the
terminal relay and the kernel layers. The next step is a test for each
missed change that matters there, starting with `verify.rs`, `probe.rs` and
`pty.rs`, and a new run of those files afterwards.
