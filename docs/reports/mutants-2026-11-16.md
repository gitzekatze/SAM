# Mutation testing, full run (2026-11-16)

> **What this is:** cargo-mutants changed the code of the four crates that
> handle untrusted input and build the sandbox (`sam-sandbox`, `sam-runner`,
> `sam-intake`, `sam-detect`) on purpose, one small change at a time, and ran
> all of SAM's tests against each change. A change the tests do not notice
> ("missed") shows a promise that no test really checks.
>
> This is one complete run on `main` at 7c01931, without `--iterate`, so
> every change has its own recorded result. It replaces the run of
> 2026-11-15, whose numbers could not be split exactly.

## Conditions of the run, and one correction

The run used no special variables, so the tests that only run in CI with
`SAM_TEST_GPG=1` did not run. That affects `sam-detect/src/signature.rs`:
in the full run 16 of its 50 buildable changes were missed (68 %). Run
again on its own with `SAM_TEST_GPG=1`, as CI runs it, only **4 of 50**
were missed (**92 %**). The numbers above are the full run as recorded;
with that correction, 412 changes were missed (85.2 % caught).

**Correction (2026-11-17): three sandbox tests skipped themselves.** Each
change was tested with the whole workspace, so SAM's helper `sam-jail-run`
was built, and most sandbox tests ran: the end-to-end sandbox test, the
hostile AppImages and every command-line test. But the tests that look for
the helper with `find_helper` did not find it, because a test program runs
from another folder of the build and `PATH` did not point to the helper.
So the breakout test, the sandbox check (`verify.rs`) and the stop test
skipped themselves, and the permission matrix and the hostile-file test
skipped their helper sections. The numbers above are therefore a lower
bound for the code those tests prove: the sandbox check, the terminal
relay, the kernel layers and stopping apps. Tests now find the helper of
their own build (`find_helper`), and the next run refuses any skip
(`SAM_REQUIRE_SANDBOX=1`).

Mutants that break SAM's cleanup left about 4,300 empty folders in the test
user's runtime folder; they were removed after the run, and later runs use
a runtime folder of their own.

## Addendum (2026-11-17): the weakest files again, and why that run was not true either

The four files that looked weakest (`probe.rs`, `verify.rs`, `pty.rs`,
`kernel.rs`) were tested again after the first cause was fixed: tests now
find SAM's helper of their own build, and `SAM_REQUIRE_SANDBOX=1` made any
skip a failure. Of 411 changes, 385 were tested, and the run reported 0
missed.

**That result is not true.** The hostile-AppImage test (`evil.rs`) still
looked for the helper only on `PATH`, so with skips refused it failed for
every change, unchanged code included. cargo-mutants' own baseline, which
would have shown this, cannot run SAM's whole suite and was switched off.
So a failing test that had nothing to do with the change "caught" it:

| | Changes |
|---|---|
| Caught by a test that works | 126 |
| "Caught" only by the always-failing test: **result unknown** | 231 |
| Timeout | 20 |
| Not buildable | 8 |
| Not tested (run stopped) | 26 |

What changed so this cannot happen again:

- `evil.rs` finds the helper of its own build, like the other sandbox tests.
- `scripts/mutants.sh` first runs the whole suite on the unchanged code and
  stops if anything fails: its own baseline in place of cargo-mutants'.
- `scripts/mutants-report.py` refuses a run in which a test never passed
  and names that test.

### The true result (re-run 2026-11-17)

The 231 unknown, 26 untested and 20 timed-out changes were run again with
these settings (whole suite on the unchanged code first, every test
running). Together with the 126 changes caught before by a working test:

| | Changes |
|---|---|
| Caught by a test | 205 |
| Caught by a time-out | 20 |
| Caught by running out of memory | 1 |
| Not buildable | 10 |
| **Missed** | **175** |

**56.4 % of the buildable changes caught** — not 100 %. The gaps are real
and sit in two of SAM's functions:

| Function | Missed | File |
|---|---|---|
| 20. The sandbox check (*Test*) shows that every setting applies | 103 | `probe.rs` 59, `verify.rs` 44 |
| 17. The app can't type into your terminal | 72 | `pty.rs` 65 |
| 13 / 16 (kernel layers) | 7 | `kernel.rs` |

So the weak files this report named were weak after all; the earlier
"tests that did not run" explained part of it, not all. Both functions
need tests that check the results, not only that the code runs: for the
sandbox check, each probe's verdict for a granted and a refused setting;
for the terminal filter, each escape code family split at every byte (an
independent review found a real bypass there the same night: leading zeros
in a control code's number, now fixed).

One change made SAM's terminal text cleaner loop forever while growing a
buffer (`pty.rs` `plain_text`, `+=` → `*=`); it filled 28 GB before the run's
own memory limit stopped it. It counts as caught (the tests never finish).
Run mutation testing inside a memory limit (locally
`systemd-run --user --scope -p MemoryMax=…`); on GitHub a job that runs out
of memory ends, and the weekly summary reports it as not finished.
